# 翻译版附加检查清单（英译启用版）

**适用前提**：被审对象是一份译本，定稿（master）可获取。单语版审校**不加载本文件**。

**当前启用范围**：中→英（`zh2en`）与英→中（`en2zh`）两个方向。多语并行（场景 B，含跨语版横向一致性）暂缓，L8 保留条目但标注「未启用」。

**核心原则**：单语版审校查的是「内部自洽」；翻译版查的是「源-靶对齐」。前者禁止给正确值，后者**有源文作基准，必须给建议译法并标源文页码**。

定级分四档：严重 / 中等 / 轻微 / **偏离**（规范偏离，单列，不占三级统计）。

---

## 方向（先读这一节）

**方向不是备注，是总开关。** 开工前只问一句「中文是翻译稿，还是英文是翻译稿」——另一版即定稿，不要再问「哪版是定稿」。结论写进 `meta.direction` 写死。

| 环节 | `zh2en`（中文定稿） | `en2zh`（英文定稿） |
|---|---|---|
| 被审文件（`loc` / `quote`） | 英文版 | 中文版 |
| 基准（`srcLoc` / `srcQuote`） | 中文定稿 | 英文定稿 |
| `scan.py` 参数 | `--lang en --source 中文.pdf` | `--lang zh --source 英文.pdf` |
| `termdrift.py` 参数 | `--direction zh2en 中文.pdf 英文.pdf` | `--direction en2zh 英文.pdf 中文.pdf` |
| verbatim 保护谁 | 保护中文值，英版须照抄 | 保护英文值，中版须照抄 |
| 残留检查 | 残留汉字页 | 残留英文段 |
| STE 子集 | 适用（`steMode: subset`） | **不适用**（`steMode: off`，不得声称合规） |
| L5 版式风险 | 字符膨胀：撑破单元格、硬断词 | 字符收缩：留白、空行、编号错位 |
| L6 索引排序 | 英文按字母序重排 | 中文按拼音序重排 |
| L7 语言质量 | 英文拼写语法冠词 | 中文错别字、翻译腔、术语生造 |
| `fix` 落点 | 改英文，标中文页码 | 改中文，标英文页码 |

**方向搞反的后果**：`fix` 指向错的一版（让客户改定稿）、verbatim 保护错的一版（把错误当基准）、
漏译查错方向（查了不存在的问题、漏了真问题）。发现方向错了，整份报告作废重做，不能局部修补。

**定级不随方向改变**：反译、索引失效、数值不一致在两个方向上后果相同。变的只是谁该改。

## L1 数值与单位（严重，零容错）

**默认口径：逐字一致。** 译制版的数值与单位须与**定稿**保持一致（`zh2en` 指中文定稿，`en2zh` 指英文定稿），**不做本地化换算**——这是常规做法，也是本技能的默认前提。仅当第 0 步确认「客户要求按目标市场换算」时，才切换为 localize 口径。

### verbatim 口径（默认，`meta.unitPolicy = "verbatim"`）

**查什么**

- 同一参数在源文与译文的数值、单位是否完全相同
- 有无擅自换算：源文 `10 L` 被改成 `2.6 gal`、`45 km` 被改成 `28 mile`
- 有无漏单位：源文 `45 L` 译成 `45`
- 有无换单位：源文 `N·m` 译成 `Nm` / `ft·lb`、`km/h` 译成 `mph`
- 单位写法是否与源文一致：大小写（`kW` / `KW`）、中点（`N·m` / `Nm`）、缩写变体（`r/min` / `rpm`、`L` / `l`）
- 数值本身是否被改：`12.3 V` → `12 V`、小数位被抹掉

**发现方法**

```
python scripts/scan.py <file_en.pdf> --lang en --source <中文定稿.pdf>
```

脚本抽取两侧「数值+单位」集合逐项比对，先按「数值相同、单位不同」配对（单位写法错误或擅自换算），剩余单边项输出三态：两侧一致 / 源文有译文无 / 译文有源文无。

**归一化规则（仅消除字符编码与数字排版差异）**

- 千分位符与数字、单位间空格：`5,000` / `5 000` / `5000` 同一值
- 字符等价异体：`℃` / `°C`、`℉` / `°F`、全角与半角

**单位写法不归一化。** `N·m` 与 `Nm`、`kW` 与 `KW`、`r/min` 与 `rpm`、`L` 与 `l` 是不同写法，必须与源文一致。
`Nm` 易与 `nm`（纳米）、`mN`（毫牛）混淆，属**可致误读的缺陷**，不得按排版差异放过。

**判别要点**

- 单位写法不一致 → **中等**，`flag` 标「单位写法」。纯大小写差异可降轻微，但 `N·m`/`Nm`、`km/h`/`kph` 这类易混淆的不降
- 「译文有、源文无」三种常见成因：擅自换算、增译了源文没有的数据、两个数被合成一个
- 「源文有、译文无」三种常见成因：漏译该段、数值在表格内未进文本层、单位丢失
- 单边项一律进主清单，`fix` 写「改回源文 X（源文第 N 页）」，**不得给出换算值**
- 表格与正文同一参数两处不同 → 按中文版第 3 类病灶处理，只报不一致，不判断哪个对

### localize 口径（仅客户明确要求时，`meta.unitPolicy = "localize"`）

此时才校验换算正确性与取整方向。换算基准与取整规则须由客户书面给出；无基准时只报「与源文不等」，不判断换算对不对。

### 例外项（`meta.localizeItems`）

个别项确需本地化——目标市场法规强制英制、燃油标号体系不同（RON↔AKI）等——逐项登记：

```
{"item": "胎压", "basis": "ECE 法规 XX 条 / 客户 2026-11-10 邮件", "approvedBy": "客户方姓名"}
```

清单内的项允许不一致；未登记的项一律按 verbatim 报。无清单即全篇零变更。

### 数字写法风格（轻微，不计违规）

千分位与空格写法不算错误，但**通篇须统一**：全篇都用 `5,000` 或全篇都用 `5000`，不能混用。脚本输出「数字写法不统一」组，逐组确认后按格式类轻微报，`fix` 写「统一为 X 写法」。

### 不属审校范围

「英文读者是否习惯 bar / ℃ / km」是客户的产品决策，不是审校问题。审校只报「与源文不一致」。**不得以「未换算成英制」为由开条目。**

## L2 安全语与法规（严重）

**查什么**

- 分级词一一对应：危险→DANGER、警告→WARNING、注意→CAUTION。**不得互换，不得合并**
- 模态强度不漂移：必须→must、应→should、可→may/can、禁止→do not / must not
- 软模态未被硬化：源文「建议」译成 must → 中等；源文「必须」译成 should → 严重
- 警示框内指令句用命令式（Keep hands clear.），不用陈述句或被动
- 法规引用按目标市场替换：GB→ECE/FMVSS/CMVSS，不得保留中国国标编号作为唯一依据
- 认证标志、警示图形（ISO 7010 类）说明文字与图形语义一致

**发现方法**

抽取全部警示框（DANGER/WARNING/CAUTION/NOTICE 及其框体），与源文警示框**逐条配对**。数量不等即为漏译或多译，先报数量差，再定位。

**判别要点**

- 源文一个警示框在译文中拆成两个，或两个合成一个 → 中等，需回改结构
- 分级词译对但框体配色/图标沿用错误级别 → 严重（读者按颜色判风险）
- 警示框内出现「should consider」「it is recommended」→ 严重，与分级冲突

## L3 源-靶忠实度（严重/中等）

**查什么**

- 漏译：整段、整句、整表行、整条列表项、图注、表头、脚注、页眉页脚
- 增译：译文出现源文没有的限制条件、数值或警告
- 误译：技术动作译错（loosen↔tighten、clockwise↔counterclockwise、front↔rear）
- 反译：否定丢失或误加（do not→do，或反之）
- 错位：段落内容跑到相邻小节

**发现方法**

按章逐段对照，**不抽样**。先比结构（段落数、列表项数、表格行列数），结构对齐后再比内容——结构差是最快的漏译信号。

**判别要点**

- 反译在安全语境下直接升严重：`do not operate` 译成 `operate` 属最高危
- 增译的限制条件若与源文另一处冲突，按逻辑矛盾处理
- 图注、表头漏译不计轻微——它们在 L5 里是版式缺陷，在 L3 里是漏译，取高不取低

## L4 术语与受控语言（中等，偏上）

**这一层是本技能唯一「必须交表」的地方。** 它查的是**源词与译词的对应关系是否一对一**，
而不是单个句子译得对不对。这类缺陷的句子语法正确、结构完全对齐，通读必然漏——必须靠流程。

**查什么**

- **一词一译**：同一个源词在译文里只有一个词族。同一源词被两个词族分裂即缺陷（「驾驶」→ driving / riding）
- **一物一译**：同一部件全篇只有一个译名，正文与表格、正文与目录、正文与索引都算
- 同一概念不得三套并存：全称 / 缩写 / 图标缩写
- 缩写首次出现是否展开（ABS → Anti-lock Braking System (ABS)）
- 不可译项未被翻译：车型号、零件号、认证编号、软件菜单项、单位符号（见 `do-not-translate.json`）
- 大小写规范：通用部件名小写（brake lever），专有名称与商标按官方写法

**发现方法：三关 + 一个回流，缺一不可**

| 关 | 命令 / 动作 | 判定力 | 处理方式 |
|---|---|---|---|
| **R1 标题层** | `termdrift.py` 的 `r1_title_drift` | `zh2en` 近乎零误报；`en2zh` 噪声较高（中文标题语序自由） | 逐组确认，词序调整类可整组排除 |
| **R2 章内近义对** | `termdrift.py` 的 `r2_synonym_pairs` | 候选级 | 逐处回原文核，不得直接上报 |
| **R3 高频词清单** | `termdrift.py` 生成的 `termdrift.md` | 强制交付物 | **填完才准出件** |
| **R4 回流拦截** | `terms.json` 的 `term_map` | 确定性 | 下次由 `scan.py` 自动拦 |

```
python scripts/termdrift.py <定稿.pdf> <被审文件.pdf> --direction zh2en -o termdrift
```

**R3 为什么是硬规则**：R1 会漏（riding 在标题层只有一种写法，抓不到），R2 噪声大（不能直接上报）。
唯一能兜住的是把「发现」变成「必须填的空格」——把源文出现 ≥20 次的实词逐个列出，
强制填「译文写法（全部）」一栏。**填这一栏的动作本身就会暴露漂移**：填「驾驶」时要把
driving 和 riding 都写进去，写的时候不可能看不见。

填完把择一结论写进 `terms.json`：

```
{"src": "驾驶", "chosen": "driving / drive", "forbid": ["riding", "ride"],
 "basis": "源文「骑行/骑乘」0 次；方向盘式 UTV", "approvedBy": "审校 2026-11-12"}
```

`scan.py` 下次直接报「译法冲突」，属确定性缺陷，可直接进主清单。

**判别要点**

- 同一部件在正文用 A、在表格用 B → 最常见，逐表核对
- 同一源词在正文用 A、在标题用 B → 次常见，R1 专抓这个
- 索引条目名与正文标题不同源 → 索引不是「翻译」出来的，是「按标题生成」出来的；两者不一致即缺陷
- 动词域最容易漂移：驾驶/行驶、检查、更换、拆卸、安装、清洁、调整——按词族整体核对，不要逐句看
- 反向（`en2zh`）同样成立：英文 driving 在中文版里被译成「驾驶」和「骑行」两套，同样是 L4 缺陷
- 英文缩写在图注里出现但正文未定义 → 中等

## L5 版式与字符集（严重，必须目视）

**查什么**

- 译文变长导致溢出：文字压图、压表线、超出文本框、跨栏、掉行（`zh2en` 高发）
- 译文变短导致版面空洞：整页留白、末页空白、编号错位、图表下方大片空行（`en2zh` 高发，且容易被当成「排版正常」放过）
- 断行与连字符：单词被硬断、连字符位置错误、URL 被断
- 缺字与乱码：方块字、问号、缺重音符号（é/ü/ñ）、特殊符号丢失
- 字体回退：译文使用未嵌入字体，打印时替换
- 编号与项目符号：译文中列表层级错乱、编号重复或跳号
- 表格：译文撑破单元格、列宽未调整、表头换行错位

**发现方法**

**必须渲染看图，文本层抓不到。** 这是翻译版最高发的严重缺陷区，也是中文版审校经验的直接延伸（第 3 步硬规则同样适用）。

**判别要点**

- 中→英字符数通常膨胀，短标签位（按钮、表头、图例）最先崩
- 图内标注文字若被重新排版，需核对该图与正文引用是否仍对应
- 文本层出现 `□`、`?`、连续 `....` → 疑似字体或编码问题，渲染确认

---

## L6 结构与导航（中等）

**查什么**

- 目录页码是否随译文页数变化重新生成
- 索引（Index）是否按目标语排序规则重排：英文按字母序、中文按拼音序，页码是否全部更新
- 索引条目名是否与正文标题**同源**（这是最高发的一处：索引常被独立翻译一遍，与正文标题对不上）
- 交叉引用措辞与目标：`see Section 5.2` 指向是否正确
- 图表编号与正文引用一致：`Fig. 12` 在正文被引用为 `Figure 12` / `Fig. 13`
- 页眉页脚：章节名是否同步翻译，是否残留中文
- 书签/大纲层级与标题层级一致

**发现方法**

`scan.py` 的目录偏差检查对译文同样有效（按书签比对标题页）。索引需人工核——字母序重排后页码是全新计算，脚本无法验证对错。

索引条目名与正文标题不同源时，可先机器取差集再人工判：抽出索引页（含 `......N` 点线）的条目名集合，与全部标题集合做差集，差集里的每条人工判「同义（可放行）」还是「不同源（要报）」。SFU1000 实例用此法一次查出 16 组不同源，通读时只注意到其中 2～3 组。

**判别要点**

- 索引页码整体偏移 → 一条报完，不逐条刷屏（同中文版第 2 类病灶）
- 英文索引条目按字母序但页码沿用中文版 → 全篇失效，属严重，不是中等

## L7 目标语语言质量（轻微，单列附表）

**查什么**（按目标语取用）

- `zh2en`：拼写、语法、冠词、单复数、时态一致
- `en2zh`：错别字、多字漏字、标点全半角、生造术语、翻译腔（「的的不休」「被字句堆叠」「英式长句不拆」）
- 两者共通：标点体系（中文全角 / 英文半角不得混用）、句末标点齐全、大小写或标题式全篇统一

**发现方法**

通读。**不进主清单**，单列「语言质量」附表，按每章条数汇总，不逐条列——否则会淹没真问题。

**判别要点**

- 语言质量问题若导致歧义或误操作 → 升入 L3，按严重/中等报
- 纯文风偏好不报（同中文版硬规则 1：不评价文风）

## L8 跨语版一致性（未启用，多语并行时开启）

**查什么**

- N 个语版的图表编号、参数值、警示条数是否一致
- 是否同源于同一主控语版（master）
- 二次转译链条（中→英→法）是否登记

**发现方法**

建「语种 × 条目」矩阵，逐格比对。

**状态**：本期不实现。启用前需先定主控语版与链条登记规则。

## 横切：逻辑一致性（方向无关，与 L1–L8 并列）

逻辑矛盾不属任何单一层面，`zh2en` 与 `en2zh` 都要做。方法见 SKILL.md 第 0b 步（台账）与第 1c 步（双通道扫描）。

**译文版的三条额外要求**

- 互斥扫描在**译文**上跑（判定对象是译文），同时回查源文：源文本身矛盾时属源文缺陷，`fix` 写「源文与译文同步修订」，不要只让译者改。
- 术语漂移与逻辑矛盾**不互相替代**：R1/R3 抓的是「同一源词分裂成两套译法」；若全篇统一译错（例如通篇 riding），R1/R3 一个字都不会报，只有属性互斥扫描能抓到。两套机制都要跑。
- 定级按后果定，不因方向改变（见下方「翻译版专属定级调整」）。

**源文侧单独出清单（`srcIssues[]`）**

对照校对 ≠ 两侧都审过。默认只审译文，源文只当基准，于是三类源文问题会漏：①源文错误被照译（权重被压成"存疑"）；
②译者若修正源文，按 verbatim 反被判偏离——机制在鼓励保留错误；③两侧一致但两侧都错（源文目录页码错、译文跟着错，
结构对位判"对齐通过"）。所以源文要再版时，必须单列源文侧清单：`loc` / `act`（必改·建议·待确认）/ `quote` / `issue`，
落在报告第五节与 Excel 独立工作表，**不占译文三级统计**。线索取 `scan.py --lang zh` 的占位／空页／目录偏差／字数异常，
外加对照中发现的笔误与字符错。

## STE 子集（规范偏离，单列，不占三级）

**仅目标语为英文时适用**（`zh2en`）。`en2zh` 时目标语是中文，STE 无从判定，`meta.steMode` 必须填 `off`，
报告中不得出现 STE 相关结论，也不得用「未命中 STE」暗示质量达标。

只采纳 6 条可客观判定的规则。**不做批准词词典校验**——Part 2 词典版权归 ASD，不能随技能分发；用户如需全量合规，自行获取官方 Issue 8 或用商业工具。

| # | 规则 | 判定口径 | 定级 |

## 翻译版专属定级调整

| 缺陷 | 单语版 | 翻译版 | 理由 |
|---|---|---|---|
| 数值/单位不一致 | 严重 | 严重（不降） | 后果相同 |
| 单位写法与源文不一致（`N·m`→`Nm`） | 中等 | 中等 | 易误读为纳米／毫牛，非排版差异 |
| 术语不一致 | 中等 | 中等（偏上） | 客户验收必查 |
| 反译（否定丢失） | 未单列 | **严重** | 安全语境下可致误操作 |
| 图注/表头漏译 | 轻微 | 中等 | 图注是操作依据，不是装饰 |
| 索引页码全错 | 中等 | **严重** | 检索功能整体失效 |
| 文风/翻译腔 | 不报 | 不报（仅附表汇总） | 同硬规则 1 |
| STE 偏离 | 不适用 | 偏离（单列） | 非错误 |
